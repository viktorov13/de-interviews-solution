# Аналитика и прогнозирование тарифов грузоперевозок

Прототип строит рыночный коридор ставок и рассчитывает прогноз за рейс в рублях без НДС. Источник — предоставленный синтетический снимок на **26 октября 2026 года**. PostgreSQL 17 хранит исходные данные, очищенные сделки и витрины. Python 3.12 запускает пакетную обработку и обучение CatBoost.

## Запуск

Требуются Docker и Docker Compose v2 или новее. Из корня репозитория выполните

```bash
docker-compose up
```

Compose запускает PostgreSQL, ждёт его готовности, загружает 300 000 сделок и выполняет пайплайн. Успешный прогон завершается событием `run_committed` в логах сервиса `pipeline` и кодом выхода 0. База остаётся доступной для проверки. Команда `docker compose up -d` выполняет тот же запуск в фоне.

```bash
docker compose logs pipeline
docker compose ps -a
docker compose exec db sh -c 'exec psql -X -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Настройки подключения и размер снимка описаны в `.env.example`. Настройки по умолчанию рассчитаны на локальный стенд с аутентификацией `trust` внутри сети Compose. Порт PostgreSQL на хост не пробрасывается. Для запуска с паролем задайте `POSTGRES_PASSWORD` и `POSTGRES_HOST_AUTH_METHOD=scram-sha-256` до первого создания тома. Снимок хранится в томе `pgdata`. При повторной инициализации исходные строки сохраняются. `N_PRICES` применяется при первом заполнении тома.

## Поток данных

```text
raw.prices + справочники
          │
          ▼
core.prices + price_body_groups + price_months ──► mart.market_corridor ──► mart.route_card
          │
          ├──► core.dq_quarantine_prices   (отклонённые строки)
          │
          └──► признаки и CatBoost ──► mart.ml_price_predictions + mart.ml_evaluation
```

- `sql/source/` содержит исходную схему и генератор. `sql/bootstrap.psql` применяет их в одной транзакции с маркером загрузки, затем создаёт слои Core и Mart.
- `etl/` классифицирует записи и обновляет Core и карантин пакетными SQL-операциями. В логе есть число прочитанных, принятых и отклонённых строк и распределение причин.
- `mart/` пересчитывает рыночные показатели. В PostgreSQL 17 используются точные упорядоченные агрегаты, ограничения зерна и индекс для выборки истории маршрута.
- `ml/` строит признаки, обучает модель на раннем окне, оценивает её на отложенном окне и сохраняет прогнозы одним `COPY`.

### Правила обработки

**Core.** Сделки с невалидной ценой или дистанцией, отрицательными весом или объёмом и неизвестным городом отправляются в карантин. Для RUB действует порог `price > 1000`. Совпадающие города допустимы при положительном расстоянии. Для USD и EUR используется точный курс на сохранённую `nearest_rate_date`. При отсутствии курса запись уходит в карантин. При дублях курса выбирается минимальный ID в паре «валюта и дата». Сохраняются заданные весовые и объёмные категории, пустые категории восстанавливаются из массы и объёма. В карантине хранится одна причина на сделку по порядку проверок.

**Рыночная витрина.** Зерно — календарный месяц из `price_dates`, пара городов, стандартная группа кузова и весовая категория. Каноническая запись города имеет минимальный `cities.id` на `gc_id`. Для кузовов используется `std_id` и дедупликация по паре «сделка и группа». При отсутствии связей используется `prices.body_type`. Сделка может участвовать в нескольких месяцах и группах, поэтому `trips_count` имеет смысл внутри ячейки. В расчёт входят только прямые факты без `outlier_mark` и с датой в `price_dates` не позднее среза. Перевозчики считаются по уникальному `organization_id` среди типов 3 и 9. MoM и YoY используют строго календарные ячейки с теми же измерениями. Для уровня HIGH свежесть считается от первого дня месяца ячейки до даты среза.

**Ограничение снимка.** Последние сделки, созданные 26 октября 2026 года после ночной разметки, имеют `outlier_mark = false` по умолчанию. Среди них могут оставаться ценовые аномалии. Core сохраняет исходный флаг, витрина и историческая ML-выборка используют его как фильтр.

### Повторный прогон и бэкфил

```bash
docker compose run --rm --no-deps pipeline
docker compose run --rm --no-deps pipeline --start-date 2026-10-05 --end-date 2026-10-12
```

Вторая команда перечитывает окно `[2026-10-05, 2026-10-12)` по `loading_date`. Границы можно задавать по отдельности. Окно также подхватывает уже загруженные сделки, дата которых изменилась, и удаляет результаты для удалённых исходных строк. Бэкфил предполагает, что Core уже загружен и содержит оба исторических ML-окна. Витрина пересчитывается целиком, чтобы изменения затронули все связанные календарные ячейки и долгосрочные заявки. Скоринг также пересчитывается целиком, чтобы удалить устаревшие прогнозы.

Один запуск обновляет Core, карантин, рыночную витрину и прогнозы в транзакции PostgreSQL с `REPEATABLE READ`. Конкурирующие запуски сериализуются advisory lock. При ошибке публикация откатывается, а потребители продолжают видеть предыдущий согласованный результат. На неизменном источнике повтор сохраняет значения данных и метрик. `scored_at` отражает время последнего скоринга.

## Модель и оценка

CatBoost использует отдельные признаки регионов и координат отправления и назначения, плечо рейса, параметры груза и кузова, год и sin/cos месяца, дня недели и дня года. Для сделки с несколькими группами выбирается группа основного кузова, если она присутствует среди связей, иначе первая по коду. Список входных полей задан явно. Ставка, её производные, агрегаты `price_group_stats` и флаг выбросов отсутствуют в признаках.

| Набор | Дата погрузки | Что входит |
| --- | --- | --- |
| Train | `[2026-07-26, 2026-10-05)` | Прямые валидные факты без отмеченных выбросов |
| Test | `[2026-10-05, 2026-10-26]` | Та же выборка на отложенном периоде |
| Future | `> 2026-10-26` | Валидные прямые заявки из Core |

CatBoost обучается только на Train в порядке даты погрузки и ID сделки с фиксированным seed. Test используется для расчёта метрик. Таргет — нормализованная ставка фактической сделки. Для Future факт и обе ошибки остаются `NULL`, даже если в исходной заявке заполнена цена.

На снимке из 300 000 сделок ETL загрузил 299 797 строк и отправил 203 в карантин. В рыночной витрине 203 644 ячейки. R², MAPE, RMSE и MAE записываются в `mart.ml_evaluation` и выводятся в событии `run_committed`.

## SQL для проверки

```sql
SELECT price_month, loading_city, unloading_city, body_group, weight_category,
       p25_trip, median_trip, p75_trip, median_km, trips_count, carriers_count,
       cv_rate, mom_pct, yoy_pct, reliability_level
FROM mart.route_card
WHERE loading_city_gcid = 1001 AND unloading_city_gcid = 1003
  AND body_group_id = 56 AND weight_category = 'FTL'
ORDER BY price_month DESC
LIMIT 12;

SELECT reason, COUNT(*) FROM core.dq_quarantine_prices
GROUP BY reason ORDER BY COUNT(*) DESC;

SELECT * FROM mart.ml_evaluation;

SELECT price_id, loading_date, body_group, actual_price_rub,
       predicted_price_rub, abs_error_rub, ape_pct
FROM mart.ml_price_predictions
ORDER BY loading_date DESC, price_id
LIMIT 10;
```

## Автоматические проверки

После успешного запуска

```bash
docker compose run --rm --no-deps --entrypoint python pipeline -m unittest discover -s tests -v
```

Интеграционная проверка добавляет фикстуру внутри транзакции с откатом. Она проверяет точный валютный курс и карантин, дедупликацию, порог округления веса, многомесячные сделки, отсечение будущих дат, перцентили и календарные сравнения. Дополнительные проверки покрывают список ML-признаков и состав прогнозов.

Чтобы проверить воспроизводимость после повторного прогона или бэкфила неизменённого снимка, выполните этот запрос до и после. Он возвращает число строк и контрольные суммы, исключая время скоринга.

```bash
docker compose exec -T db sh -c 'exec psql -X -At -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < tests/fingerprint.sql
```

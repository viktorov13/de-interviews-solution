# Аналитика и прогнозирование тарифов грузоперевозок

Прототип строит рыночный коридор ставок и рассчитывает прогноз за рейс в рублях без НДС. Источник — предоставленный синтетический снимок на **26 октября 2026 года**. PostgreSQL 17 хранит исходные данные, очищенные сделки и витрины. Python 3.12 запускает пакетную обработку и обучение CatBoost.

## Запуск

Требуются Docker и Docker Compose v2 или новее. Из корня репозитория выполните

```bash
docker-compose up
```

Compose запускает PostgreSQL, ждёт его готовности, загружает 300 000 сделок и выполняет пайплайн. Успешный прогон завершается событием `run_committed` в логах сервиса `pipeline` и кодом выхода 0. База остаётся доступной для проверки. Команда `docker compose up -d` выполняет тот же запуск в фоне.

```bash
docker compose logs pipeline
docker compose ps -a
docker compose exec db sh -c 'exec psql -X -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Настройки подключения и размер снимка описаны в `.env.example`. Настройки по умолчанию рассчитаны на локальный стенд с аутентификацией `trust` внутри сети Compose. Порт PostgreSQL на хост не пробрасывается. Для запуска с паролем задайте `POSTGRES_PASSWORD` и `POSTGRES_HOST_AUTH_METHOD=scram-sha-256` до первого создания тома. Снимок хранится в томе `pgdata`. При повторной инициализации исходные строки сохраняются. Параметр `N_PRICES` принимает положительное целое число и задаёт размер при первом заполнении тома. Для обновления существующего стенда выполните `docker compose up --build`. Команда применит схему и полностью пересчитает витрины на текущем томе.

## Поток данных

```text
raw.prices + справочники
  ├──► core.prices + price_body_groups + price_months ──► mart.market_corridor ──► mart.route_card
  │          └──► факты перевозчика ──┐
  ├──► core.forecast_requests ────────┴──► CatBoost ──► mart.ml_price_predictions + mart.ml_evaluation
  └──► core.dq_quarantine_prices
```

- `sql/source/` содержит исходную схему и генератор. `sql/bootstrap.psql` применяет их в одной транзакции с маркером загрузки, затем создаёт слои Core и Mart.
- `etl/` классифицирует записи и обновляет Core и карантин пакетными SQL-операциями. В логе есть число прочитанных, принятых и отклонённых строк и распределение причин.
- `mart/` пересчитывает рыночные показатели. В PostgreSQL 17 используются точные упорядоченные агрегаты, ограничения зерна и индекс для выборки истории маршрута.
- `ml/` строит признаки, обучает модель на раннем окне, оценивает её на отложенном окне и сохраняет прогнозы одним `COPY`.

### Правила обработки

**Core.** Сделки с невалидной ценой или дистанцией, отрицательными весом или объёмом и неизвестным городом отправляются в карантин. Для RUB действует порог `price > 1000`. Совпадающие города допустимы при положительном расстоянии. Для USD и EUR используется точный курс на сохранённую `nearest_rate_date`. При отсутствии курса запись уходит в карантин. При дублях курса выбирается минимальный ID в паре «валюта и дата». Сохраняются заданные весовые и объёмные категории, пустые категории восстанавливаются из массы и объёма. В карантине хранится одна причина на сделку по порядку проверок. Бесконечные даты и значения вне безопасного диапазона численных преобразований отклоняются, чтобы одна повреждённая запись не останавливала пакет. Диапазон от `1e-37` до `1e37` для положительных ставок и расстояний задаёт техническую границу внутри нормального диапазона float32.

**Рыночная витрина.** Зерно — календарный месяц из `price_dates`, пара городов, стандартная группа кузова и весовая категория. Каноническая запись города имеет минимальный `cities.id` на `gc_id`. Снимок справочника публикуется вместе с Core. При удалении города из RAW его последняя известная запись сохраняется для сделок за пределами текущего бэкфила. Координаты вне допустимого диапазона хранятся как `NULL`. Для кузовов используется `std_id` и дедупликация по паре «сделка и группа». При отсутствии связей используется `prices.body_type`. Сделка может участвовать в нескольких месяцах и группах, поэтому `trips_count` имеет смысл внутри ячейки. В расчёт входят прямые факты без `outlier_mark`, доступные к дате среза. Дата погрузки и дата в `price_dates` также должны быть не позднее среза. Месяц ячейки определяется по `price_dates`. Перевозчики считаются по уникальному `organization_id` среди типов 3 и 9. MoM и YoY используют строго календарные ячейки с теми же измерениями. Для уровня HIGH свежесть считается от первого дня месяца ячейки до даты среза.

**Ограничение снимка.** Последние сделки, созданные 26 октября 2026 года после ночной разметки, имеют `outlier_mark = false` по умолчанию. Среди них могут оставаться ценовые аномалии. Core сохраняет исходный флаг, витрина и историческая ML-выборка используют его как фильтр.

### Повторный прогон и бэкфил

```bash
docker compose run --rm --no-deps pipeline
docker compose run --rm --no-deps pipeline --start-date 2026-10-05 --end-date 2026-10-12
```

Вторая команда перечитывает окно `[2026-10-05, 2026-10-12)` по `loading_date`. Границы можно задавать по отдельности. Окно также подхватывает уже загруженные сделки, дата которых изменилась, и удаляет результаты для удалённых исходных строк. Бэкфил предполагает, что Core уже загружен и содержит оба исторических ML-окна. Витрина пересчитывается целиком, чтобы изменения затронули все связанные календарные ячейки и долгосрочные заявки. Скоринг также пересчитывается целиком, чтобы удалить устаревшие прогнозы.

Один запуск обновляет Core, карантин, рыночную витрину и прогнозы в транзакции PostgreSQL с `REPEATABLE READ`. Конкурирующие запуски сериализуются advisory lock. При ошибке публикация откатывается, а потребители продолжают видеть предыдущий согласованный результат. На неизменном источнике повтор сохраняет значения данных и метрик. `scored_at` отражает время последнего скоринга.

## Модель и оценка

CatBoost использует отдельные признаки регионов и координат отправления и назначения, плечо рейса, параметры груза и кузова, год и sin/cos месяца, дня недели и дня года. Для сделки с несколькими группами выбирается группа основного кузова, если она присутствует среди связей, иначе первая по коду. Список входных полей задан явно. Ставка, её производные, агрегаты `price_group_stats` и флаг выбросов отсутствуют в признаках.

| Набор | Дата погрузки | Что входит |
| --- | --- | --- |
| Train | `[2026-07-26, 2026-10-05)` | Прямые валидные факты перевозчиков без отмеченных выбросов |
| Test | `[2026-10-05, 2026-10-26]` | Та же выборка на отложенном периоде |
| Future | `> 2026-10-26` | Известные к срезу прямые заявки с валидными признаками |

CatBoost обучается только на Train в порядке даты погрузки и ID сделки с фиксированным seed. Test используется для расчёта метрик. Таргет — фактическая ставка перевозчика в рублях без НДС. Поэтому Train и Test берут типы 3 и 9 из справочника задания. Рыночный коридор использует все шесть фактических типов, как требует вопрос 2. Для Future факт и обе ошибки остаются `NULL`. Входы скоринга хранятся отдельно в `core.forecast_requests`. Заявка с валидным маршрутом может получить прогноз, даже если её цена или курс привели к ценовому карантину.

Для отсечения запоздалых данных Core хранит `available_on` как самую позднюю из доступных дат создания, изменения и использованного валютного курса. Для Train эта дата должна предшествовать 5 октября, а для Test быть не позднее даты среза. Для Future используются даты создания и изменения заявки, так как прогнозу не нужен курс сделки. При отсутствии дат Train использует дату погрузки как приближение. Источник хранит последнее состояние записи, поэтому более ранние версии признаков и ставок восстановить по этому снимку нельзя.

### Результаты на синтетическом снимке

ETL загрузил **299 797** из 300 000 сделок. В карантине 203 строки, из них 164 с невалидной ценой и 39 без точного валютного курса. Рыночная витрина содержит **203 644** ячейки.

Модель `catboost-carrier-v3` обучена на 8 479 сделках перевозчиков и оценена на 4 413 отложенных сделках. Рассчитано 5 824 прогноза для будущих заявок, включая четыре заявки с нулевой ценой.

Бейзлайн умножает расстояние на медианную ставку в рублях за километр, рассчитанную только на Train (90,40 ₽/км). Обе модели оценены на одной выборке Test.

| Метрика на Test | CatBoost | Бейзлайн |
| --- | ---: | ---: |
| R² | 0,9210 | 0,7311 |
| MAPE | 15,82% | 42,55% |
| RMSE | 50 363,15 ₽ | 92 914,24 ₽ |
| MAE | 26 815,12 ₽ | 57 387,07 ₽ |

Метрики CatBoost записываются в `mart.ml_evaluation`. Событие `run_committed` содержит также результаты бейзлайна.

### Границы прототипа

PostgreSQL выполняет преобразования рядом с данными и рассчитывает квартильные коридоры средствами SQL. Compose оркестрирует локальный запуск, а Python управляет датами обработки и одной транзакцией публикации. Полный пересчёт витрины позволяет обновлять зависимые MoM и YoY после бэкфила. Публикация использует фиксированный снимок, а параметры модели и границы выборок заданы явно. Метрики качества относятся к полному синтетическому снимку. При проверке подключения с `N_PRICES=3000` в Train оказалось 85 сделок. На этом малом срезе MAPE CatBoost составила 46,28%, у бейзлайна — 39,93%.

## SQL для проверки

```sql
SELECT price_month, loading_city, unloading_city, body_group, weight_category,
       p25_trip, median_trip, p75_trip, median_km, trips_count, carriers_count,
       cv_rate, mom_pct, yoy_pct, reliability_level
FROM mart.route_card
WHERE loading_city_gcid = 1001 AND unloading_city_gcid = 1003
  AND body_group_id = 56 AND weight_category = 'FTL'
ORDER BY price_month DESC
LIMIT 12;

SELECT reason, COUNT(*) FROM core.dq_quarantine_prices
GROUP BY reason ORDER BY COUNT(*) DESC;

SELECT e.*
FROM mart.ml_evaluation AS e
WHERE e.model_name = 'catboost-carrier-v3' AND e.as_of = DATE '2026-10-26';

SELECT price_id, loading_date, body_group, actual_price_rub,
       predicted_price_rub, abs_error_rub, ape_pct
FROM mart.ml_price_predictions
ORDER BY loading_date DESC, price_id
LIMIT 10;
```

## Автоматические проверки

После успешного запуска

```bash
docker compose run --rm --no-deps --entrypoint python pipeline -m unittest discover -s tests -v
```

Интеграционная проверка добавляет фикстуру внутри транзакции с откатом. Она проверяет точный валютный курс и карантин, дедупликацию, порог округления веса, многомесячные сделки, отсечение будущих дат, перцентили и календарные сравнения. Дополнительные проверки покрывают состав ML-признаков и прогнозов, границы доступности записей, изоляцию справочника городов, восстановление и удаление строк при бэкфиле и откат транзакции при ошибке скоринга. Отдельный сценарий проверяет скоринг заявок без пригодной ставки, далёкую дату и повреждённые числовые значения.

Чтобы проверить воспроизводимость после повторного прогона или бэкфила неизменённого снимка, выполните этот запрос до и после. Он возвращает число строк и контрольные суммы, исключая время скоринга.

```bash
docker compose exec -T db sh -c 'exec psql -X -At -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < tests/fingerprint.sql
```

На PostgreSQL 17 прошли восемь автотестов, чистый запуск, обновление прежнего тома и запуск с SCRAM. Тесты покрывают пороги 9/10 и 30 рейсов, 4/5 перевозчиков и границу свежести 30/31 день. После полного повтора, бэкфила и двух одновременных бэкфилов с перекрывающимися окнами количество строк и контрольные суммы совпали во всех девяти таблицах проверки.

На локальном Docker-стенде `EXPLAIN (ANALYZE, BUFFERS)` показал чтение по индексу даты для отбора сделок за один день (3,7 мс) и по индексу маршрута для запроса 12 ячеек карточки (0,29 мс).
